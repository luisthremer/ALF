\paragraph{Code and versions.}
All measurements use ALF (Algorithms for Lattice Fermions) with our GPU port. The CPU and the standard GPU code are the
same source (commit \texttt{410c7b04}, built with Intel oneAPI 2025.3, Intel MPI 2021.15, oneMKL 2025.3); this version is
thoroughly tested. The Intel-optimised GPU code (commit \texttt{d1060305}) adds device-side QR decompositions, fused update
kernels and asynchronous block updates. It is not yet thoroughly tested, but it already gives an idea of the performance
gains we expect in the future.

\paragraph{Test case.}
Hubbard model on an $L\times L$ square lattice, $L=16,24,32,36$ (matrix dimension $N=L^2$ up to 1296), inverse
temperature $\beta=4$, $\Delta\tau=0.1$, $U=5.25$, symmetric Trotter decomposition with checkerboard hopping, submatrix
updates ($N_\text{delay}=64$), stabilisation every 10 time slices, equal-time measurements. Each run uses one full node
and fills it: on the CPU side 112 cores as MPI ranks $\times$ OpenMP threads (1 to 8 threads per rank, no rank across a
NUMA domain), on the GPU side the four Intel Data Center GPU Max 1550 (8 tiles) with 1, 2, 4 or 8 independent Markov
chains (walkers) per tile. For every configuration 10 sweeps are timed individually after one warm-up sweep; the
throughput is the number of walkers times sweeps per node-hour, with the standard error of the 10 sweep times as
uncertainty. Table~\ref{tab:node} lists the best configuration of each side.

\paragraph{Result.}
At $L=\Lmax$, the largest lattice size with all results, one GPU node delivers \FacIntel\ times the Monte Carlo throughput of
the same node's CPUs with the Intel-optimised code (\FacBase\ times with the standard GPU code), at about \Eratio\ times
lower estimated energy per sweep. The advantage grows with the matrix dimension, because the cost of the
stabilisation (QR decompositions) and of the Green-function updates grows as $N^3$ and these parts run on the GPU.
With the Intel-optimised code the best configuration at $L\ge24$ is four walkers per tile, close to the layout used in
production (four walkers per tile, three host threads); eight walkers per tile is slower in all cases.
The production lattices reach $L=36$ and beyond; since the GPU advantage grows with $N$, we expect the factor there to be
at least as large as at the largest lattice measured here.
