ALF node throughput: GPU node vs CPU node

Test layout for comparing how many Monte Carlo sweeps one full Phase 2 node delivers on its four Max 1550 GPUs and on its 112 CPU cores. Nothing has been submitted. This page is for review before the runs start.

GPU: build_pp (410c7b04)GPU: Intel-optimised bin_batched_d1060305CPU: build_cpu-pp (410c7b04)/hppfs/work/pn73xu/di38zuw/ANTRAG_2026-11-27

Question the test answers

On one full node, what is the best throughput (sweeps per node-hour) with the GPUs, what is the best with the CPUs alone, and what is the ratio, for four lattice sizes at fixed β? Energy per sweep is then estimated from the hardware power ratings, comparing a GPU node with a notional CPU-only node (same two CPUs, no GPUs).

Node topology (measured, job 566788)

2 sockets × 56 cores Xeon Platinum 8480L, 2 hyperthreads per core, 2 NUMA domains (no sub-NUMA clustering), 256 GB each. GPUs 0 and 1 hang on NUMA 0, GPUs 2 and 3 on NUMA 1. Each GPU has 2 tiles, so each tile has 14 nearby cores.

Run matrix

Every run uses one full node and fills it. A rank is one walker (independent Markov chain). All walkers belong to one parameter set, so they synchronise once per bin.

Timing and error bars

  1. Each run writes to node-local memory (/dev/shm), so file-system noise stays out of the sweep time; the run directory is copied to ANTRAG_2026-11-27/runs/ afterwards.
  2. With NSweep = 1, rank 0 writes one bin per sweep to data.h5. A watcher logs the file's modification time with nanosecond resolution; the gap between two writes is the time of one sweep of all walkers (the slowest walker sets it, since the walkers synchronise at the bin).
  3. Sweeps 2–11 give 10 times ti. Reported: t̄ ± σ/√10 per run.
  4. Node throughput = Nwalkers × 3600 / t̄ sweeps per node-hour, with the same relative error. Best layout per device and size, then GPU/CPU ratio with propagated error.
  5. The per-sweep time includes writing one bin of equal-time observables. In production a bin holds 10 sweeps, so this test slightly favours the side whose sweeps are slower; the size of this effect is estimated from the time between the end of the last sweep and the file write.

Also logged on the GPU runs, at 1 s intervals: utilisation, power and memory per tile (xpu-smi dump, metrics 0, 1, 18). This costs nothing and gives the GPU-usage plot.
