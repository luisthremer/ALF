# Tuning guide: point defect on the GPU (delayed/submatrix) path

Measured 2026-11-07 on `nividia`: NVIDIA A30 (24 GB, sm_80), nvfortran 26.9, one process on the GPU, parameters of Jakob's production
file (`Mz = .F.`, `N_FL = 2`, `N_SUN = 2`, `U = 5`, `h0 = 1`, `Symm = T`, `Dtau = 0.1`, `Ltau = 0`, `Nwrap = 10` unless stated, beta = L).
Design and tests: [TIMEDEP_HOPPING.md](TIMEDEP_HOPPING.md). Raw tables: `docs/gpu/scripts/defect/bench/*.csv`. Times are seconds per
sweep (one sweep = up and down over all slices, includes the measurements); the first sweep includes nothing of the 1-2 s mirror setup.
The CPU numbers are the same source with `GPU=none` (nvfortran, one thread, submatrix `N_delay = 8`; the CPU path of the defect has the
static hopping as a dense matrix too, so it is much slower than a checkerboard CPU run).

## Recommended settings

| Parameter | Value | Why (measurements below) |
|---|---|---|
| `Sequential_scheme` | `"submatrix"` | 2.4-5x faster than `standard`, 1.4-2.1x faster than `delayed` at the same `N_delay` (L = 16..32) |
| `N_delay` | **32** for L <= 28, **64** for L >= 32 (`0` = automatic, selects 64) | minimum of the scan at L = 16, 24, 32; at L = 48 `N_delay` 32 is 1.7x faster than 8 |
| `Nwrap` | **10** (use 4-5 for `Mz = .T.`) | `Nwrap` 20 gives -7% time with 5e-11 Green precision (usable), 40 gives 1.6e-8 (not recommended); 5 costs +19% and +45% memory |
| `Checkerboard` | irrelevant | ignored for `h0 /= 0` on CPU and GPU (the static hopping is the dense `Op_T(1)`) |
| `Ltau` | 0 | `SpinZ_localtau` comes from the equal-time pass; `Ltau = 1` works (tau pass on device, host `ObserT`) but is slower |
| MPI | `PGI MPI GPU=nvidia` works; one rank per GPU | a second rank on the same A30 makes every chain 15-17 % slower (L = 16, MPS), 16 ranks 3.7x slower (aggregate 4.5x); see [MPI_GPU.md](MPI_GPU.md) |
| `CPU_MAX` | 23.8 (hours) | bins are written every 10 sweeps, so the run ends at the first bin boundary after `CPU_MAX`; lose at most one bin of 10 sweeps (see "time per bin") |

Environment: `OMP_TARGET_OFFLOAD=MANDATORY` (otherwise a failed device init silently runs on the CPU), one GPU process at a time. Check the
`info` file for `GPU path (gpu_state): ACTIVE` and `GPU observables: device equal-time measurement ACTIVE`.

Ready parameter files: `docs/gpu/scripts/defect/params/parameters_L<L>_beta<B>` (generated by `make_params.py`; L = 12, 16, 20, 24, 28,
32, 36, 40, 48 at beta = L; L = 48 at beta = 24, 12; L = 56 beta = 28; L = 64 beta = 32, 16, see "memory"). They are Jakob's file with
`L1 = L2 = L`, `N_Phi = L^2/2`, `Beta`, `Sequential_scheme = "submatrix"`, `N_delay`.

The speed-up is small below L = 16 (the sweep is latency bound: 175 000 small kernel launches and 220 000 stream synchronisations per sweep at
L = 32; the GPU is mostly waiting for the host) and grows with L as the dense hopping, the stabilisation and the Symm GEMMs fill the device.
The acceptance rate (0.32-0.33) and the Green precision do not depend on the scheme or `N_delay`.

Time per bin (10 sweeps) at the recommended settings: L = 24: 53 s; L = 32: 3.0 min; L = 48: 30 min. In 23.8 h: L = 32: ~470 bins, L = 48: ~48 bins.

## Memory

The stabilisation stack of the device holds `U` and `V` (Ndim x Ndim, complex) for every stabilisation point and flavour:

`peak ~ (4 * NSTM + 40) * 16 * Ndim^2 bytes + 0.3 GB (CUDA context)`, `NSTM = Ltrot / Nwrap = 10 * beta / Nwrap` (Dtau = 0.1)

(L = 48, beta = 48: 4*48+40 = 232 x 85 MB = 19.7 GB, measured 19.6 GB; L = 32: 2.8 GB, measured 3.1 GB). The host does not mirror the stack: maximum resident set of the process
at L = 36, beta = 36 (5.2 GB on the device) is 1.9 GB (`/usr/bin/time -v`).

| System | stack GPU memory | fits A30 (24 GB) | 40 GB | 80 GB |
|---|---|---|---|---|
| L = 48, beta = 48 | 19.6 GB (measured) | yes | yes | yes |
| L = 48, beta = 24 / 12 | 11.5 / 7.5 GB (formula) | yes | yes | yes |
| L = 56, beta = 28 | 23.8 GB (formula) | no | yes | yes |
| L = 64, beta = 16 | 28 GB (formula) | no | yes | yes |
| L = 64, beta = 32 | 45 GB (formula) | no | no | yes |
| L = 64, beta = 64, `Nwrap` 10 / 20 | 79 / 45 GB (formula) | no | no | 20 only (precision to be checked) |

**L = 64 cannot be started at the moment, independent of the GPU:** `Op_set` (`Operator_mod.F90`, `Det_C` of the Ndim = 4096 eigenvector
matrix underflows, `|det| = 0`) stops the Hamiltonian setup with "Eigenvector matrix has near-zero determinant" for the dense `Op_T(1)`
of the defect model (also on the CPU). L = 48 (Ndim 2304) passes. A fix has to compute the determinant phase without forming the product of 4096
LU diagonal elements (sum of logs / phases); outside this task, not changed. This was found by the attempted L = 64, beta = 16 run.

## Where the time goes (L = 32, beta = 4, 1 sweep, nsys)

44% of the GPU kernel time are 32 338 small ZGEMM launches of 52 us each (submatrix block flushes), 17% dense GEMMs (hopping, Symm),
~9% QR/LU of the stabilisation; GPU kernel time is 3.8 s of 7.5 s per sweep; 65% of the host API time is `cuStreamSynchronize`. Transfers:
see TIMEDEP_HOPPING.md section 7. Speeding up further means fewer launches per site (`gpu_lowrank_mod` blocks) rather than faster kernels.
